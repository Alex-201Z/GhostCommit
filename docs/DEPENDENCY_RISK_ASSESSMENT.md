# Dependency Risk Assessment — Phase 1A

Audit performed on 2026-06-22 with `npm audit --omit=dev`. Result: 16 production advisories (11 moderate, 5 high). A non-forced `npm audit fix --omit=dev` was attempted and did not reduce the findings. `npm audit fix --force` is prohibited here because it proposes coordinated breaking upgrades to NestJS 11 and Swagger 11 without regression evidence.

## Five high-risk findings

| #   | Package and advisory family                                                                 | Dependency chain                                          | GhostCommit exposure                                                                                                                                                    | Proposed fix                                                                                                                                                                      | Regression risk                                                                                           |
| --- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 1   | `lodash` — code injection through `_.template` imports keys                                 | backend → `@nestjs/config` / `@nestjs/swagger` → `lodash` | Low in 1A: GhostCommit does not call `_.template` or accept template options. The vulnerable package is nevertheless loaded in the API process.                         | Upgrade `@nestjs/config` and `@nestjs/swagger` in a dedicated dependency-hardening change, then pin a patched Lodash transitively if supported.                                   | Medium/high: Nest/Swagger major versions can change decorators, generated OpenAPI and bootstrap behavior. |
| 2   | `lodash` — prototype pollution through array-path bypass in `unset`/`omit`                  | backend → `@nestjs/config` / `@nestjs/swagger` → `lodash` | Low/medium: strict DTO rejection reduces attacker-controlled object shapes, but configuration and Swagger code still share the process.                                 | Same coordinated upgrade as finding 1; add malicious nested-key API regression tests before release.                                                                              | Medium/high: same major-version migration, plus possible configuration behavior changes.                  |

## Decision

No breaking dependency upgrade is bundled into Phase 1A. Runtime exposure is constrained by having no multipart or archive endpoints, strict DTO validation, and lockfile-based CI. The NestJS/Swagger/config/bcrypt upgrade must be handled as a separate security maintenance task with full API, Swagger, native-install and integration regression coverage.
